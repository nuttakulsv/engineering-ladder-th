# วิธีใช้ ladder โดยไม่ให้กลายเป็น checklist

ladder ที่ดีช่วยให้คุยเรื่องการเติบโตได้ตรงขึ้น ladder ที่ใช้ผิดจะกลายเป็นใบติ๊กที่คนพยายามเก็บให้ครบเพื่อขอขึ้นเงินเดือน เอกสารนี้คือข้อตกลงว่าเราอ่านมันยังไง

## หลักที่ใช้อ่าน

1. **ระดับวัดจากสิ่งที่ทำได้สม่ำเสมอ** ทำได้ครั้งเดียวตอนมีคนช่วยยังไม่นับ ต้องเห็นซ้ำในงานจริงอย่างน้อยหนึ่งถึงสองไตรมาส
2. **ระดับต้องผ่านเรียงกัน** คนที่ทำพฤติกรรมของ L4 ได้บางข้อ แต่ยังส่งงานระดับ L2 ไม่ได้ ยังอยู่ L2 เว็บประเมินตัวเองคิดแบบนี้เหมือนกัน
3. **ไม่ต้องครบทุกข้อ** ในแต่ละช่อง ถ้าเห็นส่วนใหญ่อย่างสม่ำเสมอถือว่าถึง (เว็บใช้เกณฑ์ 2 ใน 3) พฤติกรรมเป็นตัวอย่างของสิ่งที่จะเห็น ไม่ใช่รายการบังคับ
4. **ไม่ต้องเท่ากันทุกมิติ** คนส่วนใหญ่มีมิติที่นำหน้าและตามหลัง การเลื่อนระดับดูจากภาพรวม ปกติคือถึงระดับใหม่ในเกือบทุกมิติ และไม่มีมิติไหนต่ำกว่าระดับปัจจุบัน
5. **ขอบเขตสำคัญกว่าความเก่ง** สิ่งที่แยกระดับคือขนาดและความคลุมเครือของปัญหาที่รับผิดชอบได้ ไม่ใช่ความเร็วในการเขียนโค้ด

## ใช้ตอนไหน

- **ใน 1:1** เลือกหนึ่งมิติที่อยากพัฒนาในไตรมาสนี้ อ่านช่อง "ถ้าอยากไปถึง" ด้วยกัน แล้วหางานจริงที่จะเปิดโอกาสให้ทำสิ่งนั้น
- **ตอนวางแผนงาน** ถ้าใครต้องการหลักฐานในมิติไหน ให้ลองหางานที่เปิดโอกาสให้ทำเรื่องนั้น เช่น คนที่ต้องฝึกนำโปรเจกต์ควรได้นำงานขนาดกลางสักชิ้น
- **ตอนประเมิน** ใช้ช่อง "หลักฐานที่ใช้ตอนประเมิน" เป็นตัวตั้งคำถาม ว่ามีอะไรที่ชี้ได้บ้าง ดู [template ประเมินตัวเอง](../templates/self-review.md) และ [template สำหรับหัวหน้า](../templates/manager-review.md)
- **ตอนจ้างคน** ใช้ระดับกำหนดว่าตำแหน่งที่เปิดคาดหวังอะไร ดู [การสัมภาษณ์](hiring.md)

## สิ่งที่ไม่ควรทำ

- ใช้ ladder เป็นเหตุผลเดียวในการตัดสินเงินเดือน ladder บอกระดับ ส่วนเงินเดือนต้องดูตลาดและกระบอกเงินเดือนของบริษัทด้วย ดู [การปรับใช้กับบริษัทของคุณ](adapting.md)
- ให้คนเขียนหลักฐานครบทุกข้อเพื่อขอเลื่อนระดับ จะได้เอกสารยาวที่ไม่มีใครอ่าน ให้เลือกตัวอย่างที่ชัดที่สุด 3–5 เรื่องพอ
- เอาไปเทียบคนในทีมกันเองเป็นตาราง ladder ใช้เทียบคนกับความคาดหวังของระดับ ไม่ใช่เทียบคนกับคน
- อ่านช่อง "ยังไม่ถึงระดับนี้ ถ้า" เพื่อหาข้อตำหนิ ช่องนี้มีไว้ให้ทั้งสองฝ่ายเห็นตรงกันว่าอะไรคือสัญญาณที่ยังขาด

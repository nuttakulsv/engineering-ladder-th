# onboarding คนเข้าใหม่

เป้าหมายของ onboarding ที่ดีคือ คนใหม่ส่งงานแรกขึ้น production ได้ในสัปดาห์แรก และทำงานได้เองในงานขนาด feature ภายในประมาณสองเดือนสำหรับ L2

ใช้ [checklist นี้](../templates/onboarding-checklist.md) แล้วปรับตามทีม

## ก่อนวันแรก

- บัญชีและสิทธิ์ทุกอย่างต้องพร้อมก่อนวันแรก ทั้ง email, chat, repo, cloud และ VPN วันแรกที่นั่งรอสิทธิ์ทั้งวันทำให้คนใหม่รู้สึกว่าไม่มีใครเตรียมรอ
- เลือก buddy หนึ่งคน ไม่ใช่หัวหน้า เป็นคนที่คนใหม่ถามเรื่องเล็ก ๆ ได้โดยไม่เกรงใจ
- เตรียมงานแรกไว้ เป็นงานเล็กที่มีคุณค่าจริงและผ่าน pipeline ทั้งหมดจนขึ้น production

## สัปดาห์แรก

- วันแรกคุยกับหัวหน้าเรื่องความคาดหวัง 30, 60 และ 90 วัน
- รันโปรเจกต์บนเครื่องตัวเองได้ภายในวันแรกหรือวันที่สอง ถ้าใช้เวลานานกว่านั้น ให้คนใหม่จดทุกจุดที่ติดแล้วแก้เอกสาร
- ส่งงานแรกขึ้น production
- นั่งดูคนอยู่เวร on-call หนึ่งวัน

## เดือนแรกถึงเดือนที่สาม

- ค่อย ๆ เพิ่มขนาดงาน จาก bug เล็ก เป็น feature เล็ก และ feature กลาง
- 1:1 ทุกสัปดาห์ในช่วงนี้ ไม่ใช่ทุกสองสัปดาห์
- เมื่อครบ 30 วัน ถามคนใหม่ว่าอะไรในการ onboarding ที่ควรแก้ คนใหม่คือคนเดียวที่ยังมองเห็นสิ่งที่คนเก่าชินไปแล้ว

## สิ่งที่หัวหน้าควรวัด

- เวลาตั้งแต่วันแรกถึง PR แรกที่ merge
- เวลาตั้งแต่วันแรกถึงงานแรกที่ขึ้น production
- ความรู้สึกของคนใหม่ตอนครบ 30 และ 90 วัน

ถ้าตัวเลขเหล่านี้แย่ลงเรื่อย ๆ มักแปลว่าระบบและเอกสารซับซ้อนขึ้นโดยไม่มีใครดูแล
